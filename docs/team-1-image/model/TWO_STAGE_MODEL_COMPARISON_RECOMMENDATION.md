# Two-Stage Model Comparison and Recommendation Report

**Issue**: #33  
**Parent**: #24  
**Status**: Evaluation package ready; real field comparison not executed yet.  

## Scope

This report defines how to compare the current proposal-aligned single-stage
three-class CNN classifier against the server-first two-stage prototype on the
same expert-reviewed field-only test set.

The main proposal-aligned implementation remains the three-class CNN classifier
(`FMD`, `LSD`, `healthy`) unless thesis/project scope expansion is approved.
Two-stage work remains a reliability experiment and server-first future-work
track.

## Required inputs

Run only when these files contain real field data and predictions from the same
expert-reviewed field-only test set:

1. Field manifest from `docs/team-1-image/model/FIELD_DATA_MANIFEST.md`.
   - `label_tier=expert_reviewed`
   - `test_eligible=include`
   - weak labels excluded
   - hard negatives excluded from disease-class metrics
2. Single-stage prediction CSV for that exact test set.
3. Two-stage crop-score CSV for that exact test set.
4. Baseline metrics JSON generated by `docs/team-1-image/model/field_baseline_evaluation.py`.

Do not report real model performance unless these inputs are present. Template
CSV/JSON files under `docs/team-1-image/model/templates/` are examples only and must not be
used for thesis claims.

## Commands

```bash
python docs/team-1-image/model/field_baseline_evaluation.py \
  --field-manifest <field_manifest.csv> \

```

```bash
python docs/team-1-image/model/two_stage_fusion_evaluator.py \

  --out docs/team-1-image/model/results/two_stage_fusion_metrics.json
```

## Success gate

Two-stage prototype can be recommended for further implementation only if all
checks pass against the single-stage baseline on the same expert-reviewed
field-only test set:

| Gate | Required outcome |
|------|------------------|
| False Confident Result rate | lower than single-stage baseline |
| Macro F1 | equal or better than single-stage baseline |
| FMD recall | not worse by more than 5 percentage points |
| LSD recall | not worse by more than 5 percentage points |
| Insufficient Visual Evidence rate | ≤35% |

## Current recommendation

**Recommendation**: keep two-stage architecture as future work until real
expert-reviewed field-only test data and reviewed symptom-region annotations are
available.

Rationale:

- The evaluator, server prototype boundary, and validation-gated UX protocol are
  implemented.
- Real field comparison has not been executed because expert-reviewed Local
  Field Image test rows and corresponding two-stage crop scores are not yet
  available in the repository.
- Without that evidence, production migration would overstate scope and risk
  unsupported accuracy/reliability claims.
- Android/on-device inference should remain the existing single-stage TFLite
  fallback.

## Decision matrix

| Evidence outcome | Recommendation |
|------------------|----------------|
| All gate checks pass on real expert-reviewed field test set | Recommend further server-first implementation and validation, not immediate farmer-facing production boxes |
| False Confident Result rate improves but recall/F1 guardrails fail | Keep as research/future work; tune detector/fusion thresholds |
| Macro F1 improves but false-confident rate does not improve | Reject for reliability goal until thresholding/fusion changes reduce false confident results |
| Insufficient Visual Evidence rate >35% | Keep as future work; model too often withholds result for practical UX |
| Region UX validation shows misleading interpretation | Keep region boxes developer/debug-only |

## Limitations

- No real expert-reviewed field-only test set is committed.
- No real YOLO symptom detector has been trained/evaluated on reviewed field
  annotations in this repository.
- Template metrics are illustrative only.
- Two-stage backend path is guarded and opt-in; it is not Android production
  inference.
- Farmer-facing region visuals remain disabled unless validation evidence
  approves gated exposure.
