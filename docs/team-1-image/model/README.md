# Model Candidate Evaluation

This directory contains the model candidate evaluation artifacts for the
SapiSehat cattle disease classifier (FMD / LSD / healthy).

## Contents

| File | Description |
|------|-------------|
| `MODEL_EVALUATION_REPORT.md` | Formal comparison report of candidate models |
| `MODEL_SELECTION_REPORT.md` | Formal selection decision (generated by `model_selection.py`) |
| `KAGGLE_RUN_GUIDE.md` | Step-by-step guide for running training on Kaggle GPU |
| `TRAINING_WORKFLOW.md` | End-to-end training workflow documentation |
| `training_wrapper.py` | CLI wrapper to train/evaluate a single candidate architecture |
| `model_selection.py` | Applies selection rules (issue #17) to produce a winner (issue #21) |
| `tflite_export.py` | Exports selected Keras model to TFLite (Float32 + dynamic-range quantized) and checks parity (issue #22) |
| `evaluate_candidates.py` | Legacy script for local three-candidate evaluation |
| `results/` | Per-candidate `*_metrics.json` and confusion matrix PNGs |

## Workflow Overview

1. **Prepare dataset split** — `apps/backend/dataset_prep` generates a deterministic 70/15/15 split manifest.
2. **Train candidates** — `training_wrapper.py` trains one architecture at a time (Custom CNN, MobileNetV2, DenseNet121) using the shared manifest.
3. **Run on Kaggle** — Follow `KAGGLE_RUN_GUIDE.md` for GPU-accelerated training.
4. **Select winner** — `model_selection.py` reads `results/*_metrics.json` and applies the approved selection rules.
5. **Export to TFLite** — `tflite_export.py` converts the selected model and verifies parity for on-device deployment.

## Model Selection (issue #21)

After all three candidates have real test-split metrics in `results/`, run:

```bash
cd docs/team-1-image/model
python model_selection.py --results-dir results
# Or write the report to a file:
python model_selection.py --results-dir results --out MODEL_SELECTION_REPORT.md
```

Selection rules (priority order):
1. **Reject** any candidate with per-class F1 < 0.85.
2. **Primary metric**: highest macro F1 wins.
3. **Accuracy target**: test accuracy ≥ 0.88.
4. **Tie-breakers** (macro F1 within 0.005): accuracy > TFLite size < latency.
5. **Android viability**: TFLite size must be < 10 MB for on-device deployment.
6. **Failure policy**: if no candidate meets targets, mark best as experimental/demo.

## Training a Single Candidate

```bash
cd docs/team-1-image/model
python training_wrapper.py \
    --manifest /path/to/split_manifest.csv \
    --architecture mobilenetv2 \
    --seed 42 \
    --epochs 50 \
    --out /path/to/output_dir
```

Supported architectures: `custom_cnn`, `mobilenetv2`, `densenet121`.

The wrapper outputs per run:
- accuracy, per-class precision / recall / F1, macro F1
- confusion matrix (PNG)
- parameter count and model size
- `runtime_metadata.json`, `run_config.json`, `preprocessing.json`

## TFLite Export (issue #22)

After model selection (issue #21), export the winner to TFLite and verify parity:

```bash
cd docs/team-1-image/model
python tflite_export.py \
    --keras /path/to/selected_model.keras \
    --manifest /path/to/split_manifest.csv \
    --out tflite_out/
```

Or generate a template report without a real model (dry run):

```bash
python tflite_export.py --dry-run --out tflite_out/
```

Outputs:
- `*_float32.tflite` — Float32 baseline for parity comparison
- `*_dynamic_range.tflite` — Dynamic-range quantized app candidate
- `TFLITE_PARITY_REPORT.md` — Pass/fail against approved thresholds
- `parity_results.json` — Machine-readable parity data
- Per-variant test metrics JSON files

Parity thresholds (issue #17):
- Accuracy drop ≤ 2 pp
- Macro F1 drop ≤ 2 pp
- Per-class F1 drop ≤ 3 pp
- No class-index mismatch
- TFLite size < 10 MB
