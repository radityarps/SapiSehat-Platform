# SapiSehat Product

## Register

SapiSehat Platform

## Users

- Farmer users use Android-first mobile app for cattle records, scan flow, offline fallback, and history.
- Agency officers use web dashboard for jurisdiction-scoped triage and follow-up coordination.
- Ops/admin reviewers inspect audit logs and backend activity for release validation and investigations.
- No farmer web dashboard in first release.

## Product Purpose

SapiSehat gives early cattle disease-risk indication and follow-up prioritization.

It helps farmers record cattle, scan images, and review detection history.

It helps agency users review jurisdiction-scoped cattle disease-risk submissions, prioritize review items, and record follow-up status.

It turns farmer-submitted cattle records, image evidence, future NLP evidence, fusion results, cluster risk signals, follow-ups, and audit logs into safe agency work queues.

Success means users can quickly answer:

- which cattle records or review items need attention,
- which district-level risk signals need follow-up priority,
- what evidence state exists for each item,
- what follow-up was recorded,
- which internal action occurred and when.

It does not provide veterinary diagnosis, infected-case proof, or confirmed outbreak declaration.

## Brand Personality

Calm, precise, accountable.

Mobile app should feel like field tool for daily use: clear, quiet, trustworthy, and easy on bad screens.

Dashboard should feel like reliable operational tool for public animal-health monitoring: clear enough for daily triage, restrained enough to avoid alarm, and explicit about evidence limits.

## Anti-references

- No clinical diagnosis app framing.
- No alarmist red emergency styling.
- No decorative SaaS noise.
- No cramped government portal clutter.
- No confusing status language.
- No table-only pages with no decision support.
- No disease-positive language or interface that implies confirmed diagnosis.

## Design Principles

1. Safe wording stays near interpretation points. Any risk label, signal, or review item should make scope clear.
2. Mobile screens stay task-first.
3. Main farmer flow is login, cattle, scan, history.
4. Large touch targets matter.
5. Evidence state comes before certainty. Image-only, NLP unavailable, reliability, and conflict status must be legible.
6. Offline flow must feel reliable, not broken.
7. Tables are work surfaces, not decoration. Sorting, filtering, density, and row actions matter more than metric cards.
8. Jurisdiction boundaries are visible. Users should understand that data is scoped, not global.
9. Follow-up is action, not spectacle. Primary actions should guide officers to record useful next steps with minimal visual noise.

## Accessibility & Inclusion

Target WCAG AA.

Design for Android users on mixed-quality phones, daylight glare, and low-tech field use.

Design dashboard for agency users on mixed-quality office monitors and laptops, with possible daylight glare and long review sessions.

Use readable contrast, visible focus states, keyboard-reachable navigation and table actions, clear loading and empty states, and reduced-motion alternatives for all motion.

Do not rely on color alone for disease class, risk level, follow-up status, reliability state, or sync state.
